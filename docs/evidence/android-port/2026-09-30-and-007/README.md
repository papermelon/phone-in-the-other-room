## Implemented behavior

The Kotlin coordinator remains the only session authority. It freezes local night attribution, time zone, bedtime, wake and protected-until instants; ordinary Morning uses Swift's deterministic separate identity. Civil-calendar candidate selection and DST gap/overlap policy match current Swift. UI countdowns and transitions derive from timestamps. Clock/reboot discontinuities fail open and require repair, while a time-zone change does not move the saved occurrence. Stale terminal-parent callbacks cannot end or observe a replacement Morning.

New starts retain consent, a non-empty launchable package selection, operational readiness and repair fences. Ordinary early endings retain eligible credit and skip a future ordinary Morning; an explicit early-wake choice can start a replacement Morning now, defer the saved occurrence or skip it. Phone Away can run while a Morning is deferred and cannot accidentally cancel that separate Morning on ordinary exit. Their overlapping protection retains separate selections and observed occurrence identity. Emergency/refusal/runtime exits open all eligible protection. Requested intent, inexact boundary registration, an observed overlay event, failure and unknown coverage remain distinct.

Minimum real guest Farm state includes consumed time spans, permanent receipts/reward IDs, separate Wind Down/Phone Away meters, bonus grants, deterministic searches, inventory/capacity/pending arrivals, active sheep regrowth, wool balance and the independent Sunrise ledger. It is explicitly `localGuest`, with no verified account identity or cloud authoring path.

- Early/normal/emergency endings retain eligible time. The union of Brief Access is clipped to the actual/planned interval and subtracted once; missing recorded access rejects extra credit. Consumed spans prevent cross-run/mode double counting. Overnight credit ends at saved wake when a separate ordinary Morning exists.
- Wind Down's meter is 420 minutes; Phone Away's independent meter is 100 minutes. Timer credit grows existing active sheep's wool. The v2 bedtime bonus grants 20% search units once per frozen night within the current start window, separately from factual time and wool. Meter fills consume timer units before bonus units. v0/v1/interrupted/unknown-anchor cases do not invent historical bonuses.
- Search reward IDs, seeded randomness, guarantees, droughts, tracked sheep selection and carried fractions match Swift reference results. Minimum inventory supports 12 active arrivals, with subsequent arrivals pending. Full Farm/Shop/shearing presentation is later work.
- Morning counts eligible elapsed, including Brief Access, under Swift's independent policy: a 15-minute minimum and separate 100-minute fills granting one wool and a Sunrise search. Ordinary/planned and early-wake outcomes have their own receipts. Overnight rewards never absorb Morning rewards.

The version-2 document extends the existing `session.json`/recovery authority; there is no second reward/session database. v1 migration preserves consent, selection, generation, occurrence and recorded access, and assigns legacy reward version 0. The first recovery copy retains original v1 bytes. Terminal intent plus Morning disposition persists before platform cleanup. Effects and their settled markers then publish in one atomic generation. Acknowledgement loss retries the same permanent identities. Failed live writes retain a bounded interrupted snapshot for same-process repair and exclude the subsequent repair gap. Further writes cannot replace a pending failed transaction before repair.

The strict codec checks the checksum, schema/scope, required economic ledgers, fields, duplicates, identities and amounts. Unknown catalog values round-trip; unsupported fields/versions or malformed data do not become a replacement empty Farm. An unreadable primary may expose a non-blocking recovery snapshot, but original bytes remain write-fenced. Reinstall/reset is only an isolated-fixture repair route after exporting original bytes.

## Migration, transaction boundaries and recovery

| Scenario exercised | Observed result |
| --- | --- |
| Existing v1 occurrence with committed access → v2 | Consent, selection, occurrence/access endpoints and generation preserved; original v1 bytes retained in recovery; no historical credit/bonus. |
| Terminal-intent write fails before/after publication (JVM injected store) | Protection opens; no premature Farm effects; restart/same-process repair uses persisted/pending identity and settles once. If intent never reached disk and process dies, only the older persisted timer is knowable. |
| Native effect write fails before primary, before `AtomicFile.finishWrite`, or after primary/lost acknowledgement | Restart publishes one receipt, outcome and arrival; subsequent restart/replay leaves the exact Farm unchanged. |
| Native Morning effect write interrupted after terminal occurrence persisted | Terminal Morning remains on disk with zero pre-effect wool; restart produces one wool, one arrival and one Morning receipt; repeated replay does not duplicate them. |
| Failed live write; elapsed time advances before repair | Timer closes at failure, saved access stays bounded, repair gap earns no time and interrupted Wind Down earns no bonus. |
| Runtime failure plus effect-write acknowledgement loss | Later failure/selection/reconnection writes cannot overwrite the published effects or pending transaction; repair yields one receipt/outcome. |
| Corrupt/newer/unknown-field primary with prior recovery | Failed/unknown snapshot and repair notice; original bytes remain unchanged; all subsequent writes are fenced. |
| Invalid guest/account scope, missing ledger, combined overfull meter, negative amount, duplicate keys/new nested schema | Rejected before defaulting/normalization. Unknown sheep/rarity/tracked catalog identifiers remain lossless. |
